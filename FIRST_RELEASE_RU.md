# Главное перед первым публичным выпуском

1. Проверить на настоящих целевых устройствах полный цикл «купить → починить → продать», закрытие/повторный запуск и обновление поверх предыдущей версии без потери сохранения. Устранить вылеты, зависания, двойное списание и серьёзные ошибки управления. Автотесты уже есть, физические устройства ещё не проверены.
2. Подготовить подписанные установочные сборки для выбранных платформ. Сейчас приложены Flutter-исходники и Web release, а не готовые APK/EXE/IPA. Сначала можно выпустить одну проверенную платформу.
3. Подготовить ИИ-сервис к публичной нагрузке: проверить бюджет, текущие лимиты, защиту от массовых запросов и автоответы при сбое. Оставить общий ключ только на сервере. Игрок не должен настраивать API.
4. Оформить страницу игры, поддержку и понятное начало игры; убрать незавершённые пункты из публичного интерфейса и закрыть служебную админку. Достаточно работающего ремонта и торговли; сотрудников, новые города и новые модели можно оставить на обновления.
5. До публикации проверить права на фото, обои и брендинг, подготовить политику конфиденциальности и сведения для магазина. В 0.9 встроены фотографии разборки iFixit с CC BY-NC-SA 3.0: для коммерческого использования нужно разрешение или замена. Источники и другие неподтверждённые права перечислены в assets/repair/SOURCES.txt. Ясно сообщить, что чат — с персонажами, а текст отправляется в Google для генерации ответа; предусмотреть нужное согласие.

По состоянию на 24.10.2026: Apple требует работоспособную сборку, тестирование на устройстве, политику конфиденциальности и раскрытие передачи данных стороннему ИИ. Для Android нужна подпись выпуска. Это ориентиры подготовки, не гарантия прохождения проверки магазина.

Официальные источники:
- https://developer.apple.com/app-store/review/guidelines/ — разделы 2.1, 5.1, 5.2.
- https://developer.android.com/studio/publish/preparing — подготовка и подпись релиза.
